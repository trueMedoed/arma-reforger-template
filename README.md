# Arma Reforger — шаблон создания модов

Этот репозиторий хранит общие правила запуска новых модов для Arma Reforger. Он помогает разработчику и AI-агентам начинать каждый проект с понятной структуры, документации, плана работ и проверок в Workbench.

Сам шаблон развивается здесь, а каждый мод создаётся в отдельной папке и отдельном Git-репозитории.

## Зачем это нужно

- Сохранить единый порядок создания игровых модов, помощников Workbench и диагностических инструментов.
- Сразу подготовить описание проекта, план работ и тексты для Workshop.
- Избежать переноса чужих GUID, личных настроек и лишних ресурсов из другого мода.
- Фиксировать фактический результат: что уже реализовано, что проверено и что ещё предстоит сделать.
- Хранить историю изменений самой памятки, чтобы можно было сравнить версии и вернуться к предыдущим правилам.

## Что находится в репозитории

Основной файл — [AGENTS.md](AGENTS.md). В нём описаны:

- постановка задачи и минимальная структура нового addon-проекта;
- создание `addon.gproj`, выбор GUID и зависимостей;
- правила названий плагинов Workbench;
- проверки загрузки проекта и компиляции скриптов;
- настройка Git и первый коммит;
- подготовка английского описания Workshop, русского перевода и changelog.

Сейчас репозиторий содержит памятку и этот README. Готовый addon, скрипты и игровые ресурсы создаются отдельно под задачу конкретного мода.

## Как использовать для нового мода

1. Определить назначение мода и ожидаемый результат.
2. Прочитать [AGENTS.md](AGENTS.md) или явно указать агенту использовать этот файл как инструкции для старта.
3. Создать для мода отдельную папку рядом с папкой шаблона.
4. Подготовить каркас проекта, документацию и собственный Git-репозиторий по памятке.
5. Проверить проект в Workbench и записать результаты в README и TODO нового мода.

Пример запроса агенту:

> Создай новый мод Arma Reforger для [описание задачи] в отдельной папке каталога Mods. Используй Template/AGENTS.md как памятку для старта. Подготовь каркас, README, TODO, .gitignore и черновики текстов Workshop, затем сделай первый локальный коммит. В итоговом отчёте укажи выполненные проверки и оставшуюся работу.

Для дальнейшей работы можно скопировать `AGENTS.md` в корень нового мода и адаптировать его под этот проект. Упомянутые в памятке `Vehicle Spawn` и `Conflict Spawn Helpers` — примеры из локального каталога автора; их файлы в этот репозиторий не входят.

## Как сохранять изменения шаблона

Редактировать общие правила следует в этом репозитории. После изменения файлов:

```powershell
git diff
git add -- AGENTS.md README.md
git commit -m "Update mod creation guidelines"
git push origin main
```

`Commit` сохраняет версию в локальной истории, а `Push` отправляет её на GitHub. В GitHub Desktop это действия **Commit to main** и **Push origin**. Одного сохранения файла в редакторе недостаточно для записи в Git-историю.

Изменения памятки сами по себе не обновляют уже созданные моды. Нужные правила переносятся в их репозитории отдельно, с учётом настроек каждого проекта.
